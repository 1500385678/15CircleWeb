# Auto.md · 15CircleWeb 自动开发协同规则

> 半自动开发闭环:`Frame`(人/事实源)→`Plan`(Agent/执行态)→代码→双平台推送→`Frame` 自动更新。
> 操作者(人)只动 **"待开发功能1"**,其它全自动化。

---

## 1. 目标

解决三个痛点:
- 功能多了 → 排期乱
- 手挑任务 → 工作量大
- 做完没回写 → 状态漂移

**核心原则**:人管"做什么",Agent 管"什么时候做/怎么做"。

---

## 2. 数据源(SSOT · 事实源)

| 文件 | 角色 | 谁改 | 字段 |
|---|---|---|---|
| `.15CircleWebAutoEvolution/.15CircleWebFrame.xlsx` | **Frame** · 功能总清单(SSOT) | **人** 改"待开发功能1" · **Agent** 改其它 | 编码/名称/描述/状态(G)/进Plan日(H) |
| `.15CircleWebAutoEvolution/.15CircleWebPlan.xlsx` | **Plan** · 7天执行计划(执行态) | **Agent** | 任务名/ID/估算/风险/涉及文件/验收标准/状态 |
| `docs/api_contract.md` | API 契约 | **Agent** 自动追加 | 端点 |
| GitHub + Gitee Issues | 任务流水 | **Agent** 自动开/关 | 标题`[D-001] 名称` |

### 2.1 Frame 工作集定义

| Sheet | 含义 | 谁管 | 编码前缀 | 数量(2026-08-06) |
|---|---|---|---|---:|
| `总控` | 一页看全部 7 sheet | Agent(只读展示) | — | — |
| `核心(天天用)` | 已上线 · 天天用 | Agent 维护(只增不减) | **A** | 16 |
| `辅助(经常用)` | 已上线 · 经常用 | Agent 维护(只增不减) | **B** | 13 |
| `实验(新功能)` | 刚做完 · 待验证 | Agent 维护 | **C** | 3 |
| `待开发功能1` | **操作者(人)的唯一写入点** | **人(张勇)** | **D** | 15 |
| `待开发功能2` | 备选 · 没想好 | Agent 维护(可升 1) | **E** | 26 |
| `待开发功能3` | 只有个概念 | Agent 维护(可升 1) | **F** | 28 |

### 2.2 编号规则

- **大类字母** + **3 位序号**:`D-001` `E-015` `F-027`
- **自动重编号**:sheet 增删行后,Agent 立即按顺序重排(0 漂移)
- **不可手改编码**:操作者只填"名称"和"描述",编码由 Agent 给

### 2.3 状态字段(Frame G/H 列 · 关键!)

| 列 | 字段 | 取值 | 谁改 |
|---|---|---|---|
| **G** | 状态 | `未开发` / `计划中` / `开发中` / `已完成` / `已废弃` | Agent |
| **H** | 进 Plan 日 | `2026-08-06` 格式 · 空 = 未进 | Agent |

## 3. 三个角色

### 3.1 操作者(张勇 · 人)

**只做一件事**:打开 `.15CircleWebFrame.xlsx`,在"待开发功能1"末尾新加一行:
- 列 A:空(Agent 会填编码)
- 列 B:**功能名称**(动宾结构 · 5 字内)
- 列 C:**功能描述**(一句话 · 用户视角)
- 保存关闭

**不做的**:
- ❌ 不改其它 6 个 sheet
- ❌ 不手填编码(Agent 给)
- ❌ 不手填状态(Agent 改)
- ❌ 不动 Plan(Agent 写)
- ❌ 不直接 commit(Agent 推)

### 3.2 规划 Agent(每晚 22:00)

**触发**:`frame-to-plan-2200` cron(0 22 * * *)

**职责**:
1. 读 Frame "待开发功能1"
2. 找"未开发"状态的任务(G 列)
3. 按优先级(风险/估算/业务价值)选 N 个(默认 3 个/天)
4. 写进 Plan 下一天 sheet(估算/风险/涉及文件/验收标准)
5. 更新 Frame G 列:`未开发` → `计划中`,H 列填今天日期
6. 输出"今晚已规划 3 项"的简短报告

### 3.3 执行 Agent(每小时滚动)

**触发**:`plan-execute-hourly` cron(0 9-23 * * *)

**职责**:
1. 读 Plan,找 `状态=todo` 的任务
2. 选 1 个(单线程,避免冲突)
3. 改 Plan 状态: `todo` → `doing`
4. 开 GitHub Issue(标题 `[D-001] 名称`,跟 Frame 一致)
5. 写代码 / 改文件(限定目录,见 §5)
6. 跑 `_smoke.py` 验证(14 endpoints)
7. commit + push(GitHub + Gitee)
8. 改 Plan 状态: `doing` → `done`
9. 调 `_plan_to_frame.py` 更新 Frame:
   - D 列任务 → G=`已完成`
   - 工作集迁移:从"待开发功能1"删除该行,在"核心(天天用)"末尾加新行
   - 重新编号(所有 sheet 0 漂移)
10. 关闭 GitHub Issue(`state: closed`)

## 5. 安全约束(硬底线)

| 项 | 规则 | 原因 |
|---|---|---|
| **可改目录** | `client/js/modules/*` · `server/handlers/*` · `docs/api_contract.md` | 限定代码改动范围 |
| **不可改** | `AGENTS.md` · `.gitignore` · 已有 xlsx 历史数据 · `server/__init__.py` 版本号(自动改) | 保护元数据 |
| **单任务超时** | 4 小时 | 避免跑飞 |
| **并行上限** | 1 个任务(单线程) | 避免冲突 |
| **失败处理** | 任务失败 → Plan `状态=failed` · Frame 留 `开发中` · 不阻塞后续 | 容错 |
| **推送** | 必须先 `_smoke.py` 通过 · 失败不 push | 质量门 |
| **关键操作** | push 用 `GH_TOKEN` (User-scope env) · 不手贴 | 安全 |
| **重编号** | 任何 sheet 增删后必跑 `_frame_renumber.py` | 0 漂移 |
| **审计** | 每周日 21:00 `_frame_audit.py` 跑一次 | 兜底漂移 |

## 8. 失败处理

| 场景 | 处理 |
|---|---|
| `_smoke.py` 失败 | Plan `状态=failed` · GitHub Issue 加 `failed` 标签 · **不 push** |
| push 失败(GitHub 443) | 等 5 min 重试 · 3 次后人工 |
| 冲突(Frame 被同时改) | Frame 加文件锁标记 · 失败回滚 |
| 超时(>4h) | 强制停 · 留 `开发中` 状态 · 不阻塞 |
| 编码冲突 | 重新编号脚本优先于所有操作 |

## 9. 操作者最小操作(张三视角)

**每条新功能 = 30 秒**:

1. 打开 `.15CircleWebFrame.xlsx` → "待开发功能1"
2. 末尾新加一行:
   - A 列:空
   - B 列:**名称**(5 字内,动宾)
   - C 列:**描述**(一句话)
3. 保存
4. 关闭

**然后什么都不用管**:
- 当晚 22:00 → 规划 Agent 挑 → 写进明天的 Plan
- 明天 → 执行 Agent 写代码 → 推 GitHub + Gitee
- 完成后 → Frame 自动更新(状态/编号/工作集)
- 每周日 → 收到审计报告(本周完成 N 项 / 漂移 X 项)

## 10. 类比(给非程序员)

| 概念 | 类比 |
|---|---|
| **Frame** | 餐厅**菜单**(所有菜的清单) |
| **Plan** | **明天的备菜清单**(7 天滚动) |
| **规划 Agent** | **采购员**(每天晚上看菜单,定明天的采购量) |
| **执行 Agent** | **厨师**(按清单做菜,做完了画勾) |
| **GitHub** | **出菜窗口**(顾客看到菜的进度) |
| **审计** | **经理每周日对账**(菜和账对得上吗) |
| **编号** | **菜单页码**(菜删了,后面的页码自动前移) |
